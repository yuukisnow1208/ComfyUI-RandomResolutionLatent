# 🎲 随机分辨率空白 Latent

> `ComfyUI-RandomResolutionLatent` · 每次排队执行，自动换一个**合理的**空 latent 分辨率。
> 同一套提示词批量出图时，出来的每张图尺寸都不一样。

---

## 解决的痛点

批量出图（队列 Batch count = 10）时，`Empty Latent Image` 永远是同一个尺寸，
想换比例只能手动改宽高、重新排队，改一次出一张。

这个节点把自己**当成一个会自动换尺寸的 Empty Latent Image**：

```
Empty Latent Image ──┐                     Random Resolution Latent ── latent ──> KSampler
  宽 1024 高 1024    ├── 每次排队都一样      (每次排队自动变)        width ──> 别的节点
  改尺寸 = 重排队     ┘                     1024×1024 → 1152×896 → 896×1152 → ...
```

内置的分辨率桶全部按 **64 对齐**（SDXL / SD1.5 的训练桶），不会因为
"随手填个 1234×567" 让画面崩掉、也不会出现 VAE 报错的非 8 倍数尺寸。

## 安装

已经放进你的整合包了：`E:\AI\ComfyUI-aki-v3\ComfyUI\custom_nodes\ComfyUI-RandomResolutionLatent`

拷贝到其它机器：把整个 `ComfyUI-RandomResolutionLatent` 文件夹丢进 `ComfyUI/custom_nodes/` 即可，
**无第三方依赖**，不需要额外 pip 安装。

安装后需要**重启 ComfyUI**（绘世启动器点「重启」/ 刷新浏览器缓存），
在节点搜索里搜 `分辨率` 或 `resolution`。

## 30 秒上手

```
[🎲 随机分辨率空白 Latent] -- latent --> [KSampler] --> [VAE Decode] --> [Save Image]
```

1. 删掉原来的 `Empty Latent Image`，换成 **🎲 随机分辨率空白 Latent**
2. 它的 `latent` 接到 `KSampler` 的 `latent_image`
3. 队列面板把 **Batch count 设成 9**（或你要的张数），点「排队」
4. 每次执行都会自动换一个尺寸，节点上会显示本次用的是哪个：

```
#3  896×1152  1.03MP  |  池 9 种 · 第 3 个 · 顺序循环
```

## 关键：两种「批量」不是一回事

| 位置 | 名字 | 含义 | 尺寸 |
| --- | --- | --- | --- |
| **队列面板** | Batch count / 队列数量 | 把同一个工作流排队执行 N 次 | ✅ **每次都不一样** |
| **本节点** | batch_size | 一次执行内生成 N 张 | ❌ N 张同尺寸（喂给 KSampler 的 batch） |

**想要多种分辨率 → 用队列的 Batch count。**
`batch_size` 只在"一次采样出多张同尺寸再挑一张"时用。

> 用 API / 脚本提交也一样：同一个工作流反复 POST 到 `/prompt` 就会依次换尺寸，
> 不需要每次改 JSON。

## 参数说明

### 分辨率从哪来 · `pool_source`

| 选项 | 说明 |
| --- | --- |
| 预设桶 | 用内置的现成桶，最省心，出图最稳 |
| 自定义列表 | 完全自己写（见下） |
| 预设 + 自定义 | 两者合并去重 |
| 按目标像素生成 | 给一组**宽高比**，按目标像素实时反推尺寸 |

内置预设桶：

| 桶 | 内容 |
| --- | --- |
| `SDXL 标准桶 · 1MP (9 种)` | 1024×1024 / 1152×896 / 896×1152 / 1216×832 / 832×1216 / 1344×768 / 768×1344 / 1536×640 / 640×1536 |
| `横竖方三档 · 1MP (3 种)` | 方 / 横 / 竖 各一张，最常用 |
| `SD1.5 标准桶 · 0.4MP (8 种)` | 512 系，SD1.5、老模型用 |
| `16:9 视频帧 · 横竖 (8 种)` | 1024×576 ~ 1920×1088，喂给视频模型 / 高清放大起点 |
| `高清 2MP · Flux / Qwen (5 种)` | 1408×1408 / 1728×1152 / 1920×1088 等 |
| `方形多档 · 调试 / 头像 (5 种)` | 512² / 768² / 1024² / 1280² / 1536² |

### 自定义列表 · `custom_resolutions`

一行一个，`#` 后面是注释，**混写都认**：

```text
1024x1024
1152*896        # * 也可以
1344,768        # 逗号也可以
16:9            # 写比例 → 按「目标像素」换算，并自动对齐到 multiple_of
9:16
# 下面是别的模型的
1536x864
```

规则：
- 不是 8 的倍数会自动对齐到 8（latent 要求），并在提示里告诉你对齐成了多少
- 超出 64 ~ 8192 的会被截断
- 重复项自动去掉
- 认不出来的条目会被忽略并提示

想确认自己写对没有 → 加一个 **🔍 随机分辨率池预览** 节点，它会把最终池子列出来：

```
分辨率池：9 种  ·  来源：预设桶 (preset)
----------------------------------
 1. 1024×1024  1.05MP  1:1    2. 1152×896  1.03MP  9:7    3. 896×1152  1.03MP  7:9
 ...
```

### 怎么挑 · `pick_mode`

| 模式 | 行为 | 适合 |
| --- | --- | --- |
| 顺序循环 | 从池里 1、2、3… 依次取，取完回到开头 | **推荐**，跑一轮刚好把每种尺寸都出全 |
| 随机 | 每次随机取，可能重复 | 想要随机感；固定 seed 时序列可复现 |
| 洗牌不重复 | 每一轮内部打乱且不重复，轮与轮之间也不会撞头 | 抽卡式批量，兼顾随机和不漏 |

### 其它参数

| 参数 | 说明 |
| --- | --- |
| `start_index` | 从池里第几个开始（0 起）。想接着上次的位置继续时用 |
| `batch_size` | 同一次执行内生成几张同尺寸 latent |
| `latent_format` | `4 通道` 给 SD1.5/SDXL，`16 通道` 给 SD3 / Flux / Qwen-Image（通道数对不上时采样器会自动补齐） |
| `multiple_of` | 自动换算尺寸时的对齐倍数（SDXL 用 64） |
| `seed` | 随机模式的随机源；右边控件可设为每次随机 |
| `advance_each_run` | 关掉 = 锁住当前尺寸（当普通 Empty Latent Image 用，方便调试） |

> `start_index`、`pool_source`、预设、自定义列表、`pick_mode` 等**任一改变，计数会自动归零**，
> 也就是从池首重新开始，不用手动重置。

## 它为什么能每次都换？（技术说明，可跳过）

ComfyUI 有执行缓存：输入没变就复用上次结果。如果只是普通地算个尺寸，
第二次排队会直接命中缓存，尺寸根本不会变。

本节点重写了 `IS_CHANGED` 并返回 `NaN`，ComfyUI 会认为它**每次都变了**；
而且这个"变了"的标记会写进**缓存签名并向数据流上游传播**，
所以下游的 `KSampler` / `VAE Decode` 也会跟着重新执行，不会用旧图凑数。

计数器按节点的 `unique_id` 隔离，所以同一张图里放多个调度器互不干扰
（比如同时出横版和竖版两条线）。

## 常见问题

**Q：排队 3 次，尺寸没变？**
1. 检查 `advance_each_run` 是不是被关掉了；
2. 检查是不是把张数加在了节点的 `batch_size` 上（那样同尺寸），要加在**队列的 Batch count**；
3. 用 `pool_source = 预设桶` 但池里只有 1 种。

**Q：我想固定某个尺寸不要变？**
把 `pick_mode` 设成顺序循环、`start_index` 指定那个下标，然后关掉 `advance_each_run`。

**Q：报 `IndexError: tuple index out of range`，traceback 落在 `comfy/sd.py` 的 `vae.decode`？**

说明 `latent` 被**直接接到了 `VAE Decode`**，跳过了采样器。

Qwen-Image / Wan 这类模型在 ComfyUI 里共用 **`Wan21` latent 格式（16 通道、3 维）**，
它的 VAE 解码是按 5 维张量取 `shape[3]` / `shape[4]` 估显存的；
而本节点输出的是 4 维（B, C, H, W），直接解码就下标越界。

把 `latent` 先接进 **KSampler / KSamplerAdvanced / 自定义采样器**即可 ——
采样器会调用 `comfy.sample.fix_empty_latent_channels()`，在 latent 全零时自动
校正通道数并把 4 维 `unsqueeze(2)` 成 5 维（`comfy/sample.py:58-59`）。

> **采样器是必需的一环，不是可选项。** 空 latent 的正确流向永远是
> `调度器 → 采样器 → VAE Decode`，从来没有 `调度器 → VAE Decode` 这种接法。

**Q：视频模型 / WAN、LTX 能用吗？**
本节点只产出图片 latent（4 或 16 通道、8 倍下采样）。视频模型的空 latent
请继续用它自己的节点，可以用本节点的 `width` / `height` 输出去驱动那些节点。

**Q：为什么第一张是 1024×1024？**
顺序循环从池首开始；想要别的起点就改 `start_index`。
