# 🎲 随机分辨率空白 Latent

[![ComfyUI](https://img.shields.io/badge/ComfyUI-custom%20node-1f6feb)](https://github.com/comfyanonymous/ComfyUI)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

> **ComfyUI 自定义节点** — 批量出图时，让每张图的尺寸都不一样。

它是一个**可以直接替代 `Empty Latent Image` 的节点**，区别只有一点：**每次排队执行，它都会自动换一个尺寸。**

```
第 1 张  1024×1024    第 2 张  1152×896    第 3 张  896×1152
第 4 张  1216×832     第 5 张  832×1216    第 6 张  1344×768   ……
```

节点在中文界面显示为 **🎲 随机分辨率空白 Latent**，英文界面显示为 **Random Resolution Empty Latent**。

## 解决什么问题

用原生 `Empty Latent Image` 批量出图时，尺寸是写死的：

| 场景 | 原生 Empty Latent Image | 本节点 |
| --- | --- | --- |
| 队列 Batch count = 9 | 9 张图全是 1024×1024 | 9 张图尺寸各不相同 |
| 想换个比例 | 手动改宽高 → 重新排队，一次只出 1 张 | 不用管，自动轮换 |
| 填了个 1234×567 | 非 8 倍数，可能报错或画面异常 | 自动对齐到 8 的倍数，并提示你 |
| 同一提示词想要横版 + 竖版 + 方版 | 改三轮参数、排三轮队列 | 队列数字填 3，一次拿全 |

**一句话**：把它当成"一个会自动换尺寸的 Empty Latent Image"，其它接线方式一律不变。

## 快速开始

```
[🎲 随机分辨率空白 Latent] --latent--> [KSampler] --> [VAE Decode] --> [Save Image]
```

1. 删掉原来的 `Empty Latent Image`，换成 **🎲 随机分辨率空白 Latent**

4. 每次执行都会自动换一个尺寸，节点上会实时显示本次用的是哪个：

```
#3  896×1152  1.03MP  |  池 9 种 · 第 3 个 · 顺序循环
```

用 API / 脚本提交也一样：**同一个工作流反复 POST 到 `/prompt`**，就会依次换尺寸，不需要每次改 JSON。

## 两个节点

### 节点一：随机分辨率空白 Latent

主力节点，等价于"会自动换尺寸的 Empty Latent Image"。

- **输入**：11 个界面参数，控制尺寸池怎么来、怎么挑、出什么格式（见[参数速查表](#五参数速查表)）；随机源内置，界面不显示 `seed`
- **输出**：`latent`（喂给采样器）、`width`、`height`（可接到别处复用）、`info`（本次调度信息）
- 节点上直接显示本次选了哪个尺寸，不用猜

### 节点二：随机分辨率池预览

一个**辅助核对**节点，不参与采样。

把它的参数和主节点**设成完全一样**，它就会把最终的分辨率池一条条列出来：

```
分辨率池：9 种  ·  来源：预设桶 (preset)
----------------------------------
 1. 1024×1024  1.05MP  1:1     2. 1152×896  1.03MP  9:7     3. 896×1152  1.03MP  7:9
 4. 1216×832   1.01MP  19:13   5. 832×1216  1.01MP  13:19   6. 1344×768  1.03MP  7:4
 7. 768×1344   1.03MP  4:7     8. 1536×640  0.98MP  12:5    9. 640×1536  0.98MP  5:12

提示：
· 「1002x998」不是 8 的倍数，已对齐为 1000×1000
```

**什么时候用它**：自定义列表写错了、不确定某组预设里到底有哪些尺寸、或者想确认两个节点的池子是否一致。它会把"被忽略的条目"和"被自动修正的尺寸"都明确告诉你。

## 功能详解

### 一、分辨率池：尺寸从哪来

由 `pool_source` 决定，四选一：

| 选项 | 说明 | 适合谁 |
| --- | --- | --- |
| **预设桶 (preset)** | 用内置的现成尺寸组，像素全部对齐到 64 | **新手首选**，出图最稳 |
| **自定义列表 (custom)** | 完全自己写 | 有明确尺寸要求时 |
| **预设 + 自定义 (merge)** | 两者合并、自动去重 | 在预设基础上加几个特殊尺寸 |
| **按目标像素生成 (megapixel)** | 给一组**宽高比**，按目标像素实时反推尺寸 | 想要"同像素不同比例"的成套图 |

#### ① 预设桶

`preset_group` 选组，共 6 组：

| 预设组 | 尺寸 | 用途 |
| --- | --- | --- |
| **SDXL 标准桶 · 1MP (9 种)**（默认） | 1024×1024 / 1152×896 / 896×1152 / 1216×832 / 832×1216 / 1344×768 / 768×1344 / 1536×640 / 640×1536 | SDXL 训练时的标准桶，出图质量最有保障 |
| **横竖方三档 · 1MP (3 种)** | 1024×1024 / 1216×832 / 832×1216 | 只想一次拿到横、竖、方各一张 |
| **SD1.5 标准桶 · 0.4MP (8 种)** | 512×512 / 512×768 / 768×512 / 640×640 / 576×768 / 768×576 / 448×768 / 768×448 | SD1.5 及更老的模型 |
| **16:9 视频帧 · 横竖 (8 种)** | 1024×576 / 1344×768 / 1536×864 / 1920×1088 / 576×1024 / 768×1344 / 864×1536 / 1088×1920 | 视频模型、宽屏壁纸、高清放大起点 |
| **高清 2MP · Flux / Qwen (5 种)** | 1408×1408 / 1728×1152 / 1152×1728 / 1920×1088 / 1088×1920 | Flux / Qwen-Image 等大模型直出 2MP |
| **方形多档 · 调试 / 头像 (5 种)** | 512² / 768² / 1024² / 1280² / 1536² | 测试不同分辨率下的表现，或做头像 |

> 这些桶里的像素数**全部是 64 的整数倍**，所以不会出现 VAE 报错、噪点、画面撕裂这类由尺寸引起的问题。

#### ② 自定义列表（`custom_resolutions`）

界面上是一个**格子编辑器**：每个分辨率一张小卡片，输入宽和高、点「添加」就多一格，点格子上的 `×` 就删掉。

- **宽输入框支持直接粘贴一段列表**：`1024x1024, 1152x896` 这种一次全加进来
- **宽输入框里也可以写比例**：`16:9` → 按「目标像素 megapixels」实时换算成实际尺寸
- 尺寸会**自动对齐到 8 的倍数**（比如 `1000×1002` 会存成 `1000×1000`），超界自动截断
- 重复的尺寸不会重复添加；「清空」一键移除全部
- **双击格子 = 禁用 / 恢复**：临时不想用某个尺寸又不想删掉它，双击一下即可。禁用的格子显示为灰色划线样式，**不参与调度但保留在列表里**，再双击就恢复

底层存储是每行一个 `1024x1024` 的文本（禁用的条目带 `!` 前缀），所以**旧工作流完全兼容**。写法非常宽松，下面几种**混着写都能认**：

```text
# 井号后面是注释，会被忽略
1024x1024
1152*896          # 星号也可以
1344,768          # 逗号也可以
1024×1024         # 中文乘号也可以
16:9              # 写比例 → 按「目标像素 megapixels」实时换算
9:16
!1152x896         # 行首叹号 = 禁用（保留但不参与调度）

# 换个模型的尺寸也行，混在一起没关系
1536*864
```

**解析规则（做了什么修正都会提示你）**：

| 情况 | 处理 |
| --- | --- |
| 分隔符是 `x` `X` `*` `×` `,` `，` | 当作**宽 × 高**直接使用 |
| 分隔符是 `:` `：` | 当作**宽高比**，配合 `megapixels` 换算成实际尺寸 |
| **行首 `!`** | 该条目被**禁用**（保留在列表里但不参与调度，双击格子可恢复） |
| **不是 8 的倍数** | 自动对齐到最近的 8 的倍数，并明确告诉你改成了多少 |
| **小于 16** | 该条目被忽略（太小了没有意义） |
| **大于 8192** | 截断到 8192 |
| **重复项** | 自动去掉 |
| **认不出来的内容** | 忽略，并在提示里列出来告诉你 |

举个例子，输入这两行：

```text
1002x998
16:9
```

- `1002x998` 不是 8 的倍数 → **自动对齐为 `1000×1000`**，并提示你做过修正
- `16:9` → 按 `megapixels = 1.0` 换算成 `1344×768`（约 1.03MP）

**写完不放心？** 加一个[随机分辨率池预览](#节点二随机分辨率池预览)节点对一下。

#### ③ 预设 + 自定义（合并）

先放预设桶的全部尺寸，再接上自定义列表的尺寸，**重复的自动去掉，顺序保留**。

适合"在标准桶基础上补充几个特殊尺寸"的场景。

#### ④ 按目标像素生成（`megapixel`）

不看固定尺寸表，而是给一组**宽高比**（`aspect_ratios`），按 `megapixels` 指定的目标像素实时算出尺寸。

`aspect_ratios` 在界面上同样是**格子编辑器**：每个比例一张小卡片，输入 `3:2` 或 `1.85` 点「添加」，支持一次粘贴 `1:1, 4:3, 16:9`，点 `×` 删除、「清空」全清。

```
aspect_ratios = 1:1, 3:2, 2:3, 16:9, 9:16, 21:9, 9:21
megapixels    = 1.0
```

宽高比的写法同样宽松，这几种都认：

```text
1:1, 3:2, 2:3, 16:9        # 冒号
16/9, 9/16                  # 斜杠
1.85, 2.39                  # 直接写小数（宽 ÷ 高）
```

它会按 `宽 = √(总像素 × 比例)`、`高 = √(总像素 ÷ 比例)` 算出来，再对齐到 `multiple_of`。

**用途**：想要一整套"像素量一致、比例不同"的图，或者想要某个不常见的比例（比如 21:9 超宽）。

### 二、挑选策略：怎么选

由 `pick_mode` 决定。假设池子是 `[A, B, C, D]` 四种尺寸：

| 模式 | 行为 | 连续 8 次的结果 | 适合 |
| --- | --- | --- | --- |
| **顺序循环 (sequential)**（默认） | 从池首开始依次取，取完回到开头 | `A B C D A B C D` | **推荐**。队列填池子大小，一轮刚好把每种尺寸出全，不重不漏 |
| **随机 (random)** | 每次从池里随机取，**可能重复** | `B D B A C A D C` | 想要随机感，不介意重复 |
| **洗牌不重复 (shuffle)** | 每一轮内部打乱且不重复，轮与轮之间也不会"撞头" | `C A D B A C B D` | 抽卡式批量，随机但不漏 |

**几个细节**：

- **随机模式每次排队独立随机**：内部自带随机源，界面上**没有 `seed` 控件**——对绝大多数用户来说随机就是随机，不需要关心种子。想要可控的序列，用顺序循环或洗牌模式。
- **洗牌模式会避免"撞头"**：如果新的一轮第一个恰好等于上一轮的最后一个，它会自动把第一个挪到后面，避免连着出同一个尺寸。
- **临时去掉某些尺寸**：双击自定义列表里的格子禁用它即可，不用删——改主意了再双击恢复。
- **关键参数一改，计数自动归零**：换预设组、改自定义列表、改 `pick_mode`……任何一项变化，计数都会自动重置回起点，不需要你手动清理什么。

### 三、尺寸为什么是合理的

因为本节点会主动把尺寸约束在安全范围内：

| 约束 | 值 | 原因 |
| --- | --- | --- |
| 对齐倍数 | 8 的倍数（`multiple_of` 默认 64） | VAE 下采样 8 倍，非 8 倍数会导致报错或画面异常 |
| 最小边 | 64 | 再小就出不了有意义的画面 |
| 最大边 | 8192 | 防止显存直接爆掉 |
| 内置桶 | 全部 64 对齐 | 贴合 SDXL / SD1.5 训练时的标准桶 |

`multiple_of` 一般不用动：SDXL 用 64，SD1.5 的低分辨率场景可以用 32 或 8。

### 四、输出

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `latent` | LATENT | 本次选中的空 latent，**接到采样器的 `latent_image`** |
| `width` | INT | 本次宽度，可以接到别的节点复用（比如拿来拼文件名的前缀） |
| `height` | INT | 本次高度，同上 |
| `info` | STRING | 本次调度信息，也可以接文本节点写进图片元数据 |

同时节点上会显示一行状态，形如：

```
#3  896×1152  1.03MP  |  池 9 种 · 第 3 个 · 顺序循环
```

含义：本次是第 3 次执行 · 尺寸 896×1152（约 1.03 百万像素）· 池子共 9 种 · 用的是池里第 3 个 · 挑选模式是顺序循环。

### 五、参数速查表

#### 分辨率池相关

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `pool_source` | 下拉 | `预设桶 (preset)` | 尺寸从哪来，见[上文](#一分辨率池尺寸从哪来) |
| `preset_group` | 下拉 | `SDXL 标准桶 · 1MP (9 种)` | 用哪组预设桶，共 6 组 |
| `custom_resolutions` | 格子编辑器 | 4 个示例尺寸 | 自定义尺寸列表，见[上文](#②-自定义列表custom_resolutions) |
| `megapixels` | 浮点 0.05 ~ 8.0 | `1.0` | 目标像素（百万）。写比例时、"按目标像素生成"时都按它换算 |
| `aspect_ratios` | 格子编辑器 | `1:1, 3:2, 2:3, 4:3, 3:4, 16:9, 9:16, 21:9, 9:21` | "按目标像素生成"模式使用的宽高比列表 |
| `multiple_of` | 整数 8 ~ 256 | `64` | 自动换算尺寸时的对齐倍数 |

#### 调度相关

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `pick_mode` | 下拉 | `顺序循环 (sequential)` | 挑选方式：顺序 / 随机 / 洗牌不重复 |
| `batch_size` | 整数 1 ~ 64 | `1` | **同一次执行内**生成几张同尺寸 latent。要"不同尺寸"请用队列的 Batch count |
| `latent_format` | 下拉 | `SD1.5 / SDXL (4 通道, ÷8)` | latent 通道数与下采样倍数，见下方说明 |
| `advance_each_run` | 布尔 | `开` | 关掉 = 锁住当前尺寸，当普通 Empty Latent Image 用 |

> **界面上所有参数都带中文显示名**（`pick_mode` → 挑选模式、`pool_source` → 分辨率来源、`advance_each_run` → 每次排队换尺寸……），上表保留英文名是为了对照工作流文件和 API。
>
> **没有 `seed`**：随机源内置在节点里，每次排队独立随机，不需要你设置任何种子。

**`latent_format` 怎么选**：

| 选项 | 用于 |
| --- | --- |
| `SD1.5 / SDXL (4 通道, ÷8)` | SD1.5、SD2、SDXL 及其衍生模型（默认） |
| `SD3 / Flux / Qwen-Image (16 通道, ÷8)` | SD3、Flux、Qwen-Image 等新架构 |

> 选错了也不用慌——只要 latent 走采样器，采样器会自动把通道数纠正过来（见[坑 2](#坑-2latent-必须接采样器不能直接接-vae-decode)）。但**按你实际用的模型选对**，语义上更清晰。

## 实用配方

**① 一轮跑完全部尺寸**（最常用）

```
pool_source = 预设桶 (preset)
preset_group = SDXL 标准桶 · 1MP (9 种)
pick_mode   = 顺序循环 (sequential)
→ 队列 Batch count 填 9，排队
```

结果：9 张图，9 种不同尺寸，每种恰好一张。

**② 每轮随机**

```
pick_mode = 随机 (random)
→ 队列 Batch count 填 20
```

每次排队独立随机，可能重复。要"随机但不漏"请看下一条。

**③ 抽卡式：随机但不漏尺寸**

```
pick_mode = 洗牌不重复 (shuffle)
→ 队列 Batch count 填 9
```

一轮 9 张，尺寸随机排列但**不重复**；下一轮重新洗牌，且不会和上一轮的结尾撞车。

**④ 同像素量、不同比例的一整套**

```
pool_source   = 按目标像素生成 (megapixel)
aspect_ratios = 1:1, 4:3, 3:4, 16:9, 9:16, 21:9
megapixels    = 1.0
pick_mode     = 顺序循环 (sequential)
→ 队列 Batch count 填 6
```

**⑤ 在标准桶上加几个自己的尺寸**

```
pool_source        = 预设 + 自定义 (merge)
preset_group       = SDXL 标准桶 · 1MP (9 种)
custom_resolutions = 2048x1152     ← 加两个 2K 尺寸
                     1152x2048
→ 队列 Batch count 填 11
```

**⑥ 调试时锁定尺寸**

```
advance_each_run = 关
```

此时它完全等价于一个普通 `Empty Latent Image`，反复排队都用同一个尺寸，方便你对比其它变量的影响。

**⑦ 临时跳过某几个尺寸**

双击自定义列表里不想用的格子，让它们变成灰色划线状态即可——这些尺寸保留在列表里但不参与调度，改主意了再双击恢复。适合"这批不想要竖图"这类临时调整。

## 两个最容易踩的坑

### 坑 1：队列 Batch count 与节点 batch_size

**这是最容易搞混的一点**，两个"批量"完全不是一回事：

| 位置 | 名字 | 含义 | 出来的尺寸 |
| --- | --- | --- | --- |
| **队列面板** | Batch count / 队列数量 | 把同一个工作流**排队执行 N 次** | ✅ **每次都不一样** |
| **节点内** | `batch_size` | **一次执行内**生成 N 张 | ❌ N 张必然同尺寸 |

```
想要多种分辨率 → 用「队列面板」的 Batch count。
```

节点里的 `batch_size` 是给"一次采样出多张同尺寸、再挑一张"这种玩法用的。它是同一个张量批次，形状必须一致，所以不可能尺寸不同。

> 用 API 提交时同理：把同一个 prompt **反复 POST** 到 `/prompt` 就是"多次执行"，会依次换尺寸。

### 坑 2：latent 必须接采样器，不能直接接 VAE Decode

**正确的流向只有一种**：

```
🎲 随机分辨率空白 Latent → 采样器（KSampler 等） → VAE Decode → Save Image
```

如果你把 `latent` **直接**接到 `VAE Decode`，跳过了采样器，在使用 Qwen-Image、Wan 这类模型时可能会看到：

```
IndexError: tuple index out of range
```

**原因**：Qwen-Image 在 ComfyUI 里共用 `Wan21` latent 格式（16 通道、**3 维**），它的 VAE 解码是按 5 维张量取下标来估显存的。而本节点输出的是标准的 4 维空 latent（B, C, H, W），直接解码就下标越界了。

而**采样器会做一次必要的修复**：它调用 `comfy.sample.fix_empty_latent_channels()`，在 latent 全零时自动校正通道数，并把 4 维 `unsqueeze(2)` 升成 5 维。所以只要经过采样器，一切正常。

**记住**：空 latent 永远是"先生成 → 再采样 → 最后解码"，没有"直接解码"这种接法。

## 常见问题

**Q：排队 3 次，但尺寸没变？**

按顺序检查三点：

1. `advance_each_run` 是不是被关掉了？（关掉就是锁定模式）
2. 张数是不是加在了**节点的 `batch_size`** 上？要加在**队列面板的 Batch count**（见[坑 1](#坑-1队列-batch-count-与节点-batch_size)）
3. `pool_source` 选的是"预设桶"，但 `preset_group` 那组里是不是只有 1 个尺寸？

**Q：我想固定用某个尺寸，不要变。**

关掉 `advance_each_run`（每次排队换尺寸）即可锁定当前尺寸。想让锁定的是某个特定尺寸：把自定义列表里只留那一个，或用顺序循环模式多排几次到它为止再锁定。

**Q：第一张为什么总是 1024×1024？**

顺序循环模式从池首开始取，这是设计行为。想要随机感，用**随机**或**洗牌不重复**模式。

**Q：双击禁用的格子还在列表里，会出图吗？**

不会。禁用的条目（行首带 `!`）保留在列表里但**不参与调度**，状态提示里也会列出"已禁用 N 项"。再双击就恢复。

**Q：自定义列表里写错了会怎样？**

不会崩。写错的条目会被忽略，非 8 倍数的会被自动对齐——具体发生了什么，在**节点的状态显示**和 **随机分辨率池预览**节点的输出里都会明确列出来。

**Q：随机模式可以复现吗？**

界面上没有 `seed` 控件，每次排队都是一次新的随机。想要确定性的序列，用**顺序循环**或**洗牌不重复**。

**Q：视频模型（Wan、LTX 等）能用吗？**

本节点产出的是**图片** latent（4 或 16 通道、8 倍下采样）。视频模型的空 latent 请继续用它自己的节点；不过你可以把本节点的 `width` / `height` 输出接过去复用，省得手动同步尺寸。

**Q：能在同一张图里放多个本节点吗？**

可以。每个节点的计数是**互相隔离**的（按节点 ID 区分）。比如一条线出横版、一条线出竖版，两个节点各自轮换，互不干扰。

**Q：和已有的分辨率选择类节点冲突吗？**

不冲突。像 `ComfyUI-TT-Resolution_selector-Node` 这类节点输出的是**整数**（宽、高），需要你自己接到 `Empty Latent Image` 上；本节点直接输出 **LATENT**，是端到端替代 `Empty Latent Image` 的方案。两者甚至可以配合使用。

## 工作原理（可选阅读）

**为什么它每次都能真正换尺寸？**

ComfyUI 有一套执行缓存机制：节点的输入没变，就直接复用上次的结果，不再重新执行。

如果只是"计算一个尺寸"这种纯函数式的节点，第二次排队时输入完全一样，会**直接命中缓存**——尺寸根本不会变。这是这类需求最容易翻车的地方。

本节点的做法是重写 `IS_CHANGED` 并返回 `NaN`：

```python
@classmethod
def IS_CHANGED(cls, advance_each_run=True, **_kwargs):
    return float("NaN") if advance_each_run else "resolution-scheduler-locked"
```

`NaN != NaN` 恒成立，ComfyUI 因此判定"这个节点每次都变了"，强制重新执行。更关键的是，这个"已变化"标记会**写进缓存签名，并沿数据流向上传播**，所以下游的 `KSampler`、`VAE Decode` 也会跟着重新执行，不会拿旧图凑数。

计数器按节点的 `unique_id` 隔离（隐藏输入），因此同一张图里放多个调度器互不干扰；而当分辨率池相关的关键参数发生变化时，签名不匹配会自动触发计数归零，从池首重新开始。

> 顺带一提：随机源（`seed`）被**特意排除**在签名之外，它每次排队都可能变化，进入签名反而会让计数不断被重置。它也不在界面上显示——对使用者来说那是无意义的噪音。
